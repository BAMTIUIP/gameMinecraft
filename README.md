# gameMinecraft

**ORE RUSH** — воксельная игра от первого лица (React + Vite + Three.js + Tailwind), рассчитанная на платформу [Яндекс Игры](https://yandex.ru/games/).

## Команды

| Команда | Что делает |
| --- | --- |
| `npm ci` | ставит зависимости |
| `npm run dev` | dev-сервер Vite |
| `npm run build` | собирает игру в **один файл** `dist/index.html` (JS и CSS внутри него) |
| `npm run yandex:check` | проверяет `dist/` на требования архива Яндекс Игр |
| `npm run yandex:zip` | собирает игру, проверяет размер/имена файлов и создает `release/ore-rush-yandex.zip` |
| `npm run preview` | локальный просмотр собранной игры |

## Процедурная природа

В мире есть летние зелёные леса и луга с ярусными соснами, отдельные осенние леса с клёнами и янтарной листвой, а также зимние ели с плотными снежными кронами, редкими хвойными ветвями и голыми стволами. Среди обычных деревьев встречаются широкие и ярусные дубы с раскидистыми ветвями, берёзы, яблони и плакучие ивы; осенью ивы тоже надевают золотую листву. В тёплых биомах растут большие сакуры с изогнутыми стволами и раздельными розовыми кронами, а также жакаранды с фиолетовыми соцветиями. В джунглях и пустынных оазисах генерируются кокосовые и банановые пальмы с веерными, широкими, высокими и поникающими кронами. Цветочные поляны подбирают виды под биом: от ромашек и тюльпанов до лаванды и осенних астр.

Звук тоже процедурный: в проекте нет ни одного аудиофайла, всё синтезируется в WebAudio на лету. Кроме ударов, шагов и интерфейса есть старое дерево и живой мир: крышка сундука со скрипом откидывается (а при повторном нажатии коротко скрипит ещё раз), а звери подают голос — корова мычит, овца блеет, свинья хрюкает, кошка мяукает. Птицы и пчёлы поют сами, когда игрок рядом: игра время от времени выбирает одного зверя поблизости, и он зовёт — тем громче и яснее, чем ближе, с панорамой в ту сторону, где он стоит, и с приглушением, если голова игрока под водой. При ударе животное вскрикивает своим голосом, при смерти — тянет его вниз, а враждебные мобы рычат в момент атаки. Детёныши отвечают более высоким голосом, взрослые каждый раз чуть иначе.

## Сундуки с сокровищами

Сундуки генерируются по миру в нескольких видах: по одному оформлению на каждый биом (равнины, осень, зима, джунгли, пустыня, каньон, вулкан), а под водой — отдельный затонувший сундук, обросший водорослями, ракушками и морской звездой. Они появляются в части безопасных построек, в открытых и закрытых пещерах и на достаточно глубоком морском дне. Открыть сундук можно клавишей E: содержимое детерминировано сидом и координатами, чаще всего это ресурсы и руды, изредка — редкая броня и незеритовые слитки.

Сундук многоразовый: после первого вскрытия он остаётся в мире в состоянии «открыт» — крышка откидывается назад отдельной анимированной деталью, внутри видны тёмное дно, слабое свечение и оставшиеся ресурсы. Это состояние хранится в самом мире (отдельный идентификатор открытого сундука в сетке блоков), поэтому переживает сохранение и загрузку мира, а на крышку по-прежнему можно навести прицел: подпись подскажет, что сундук пуст, а повторное нажатие E заставит крышку скрипнуть.

## Размер и архив для Яндекс Игр

Для публикации загружается **не весь проект**, а ZIP с содержимым `dist/`. `node_modules/`, исходники, `package-lock.json` и dev-зависимости в архив не попадают.

Актуальные требования Яндекса к архиву ([загрузка игры](https://yandex.ru/dev/games/doc/ru/console/add-new-game), пункты [1.21–1.22 требований](https://yandex.ru/dev/games/doc/ru/concepts/requirements#1-21)):

- содержимое архива **до сжатия** — не более **100 МБ**;
- в корне архива есть `index.html`;
- в именах файлов и папок нет пробелов и кириллических символов.

В проекте сборка уже оптимизирована под эти ограничения: Vite + `vite-plugin-singlefile` собирают игру в один минифицированный `dist/index.html`, без внешних ассетов и без `node_modules`. Дополнительно есть внутренний безопасный бюджет **20 МБ** — скрипт `npm run yandex:check` предупредит, если `dist/` станет больше него, хотя официальный лимит Яндекса выше.

Команда для релиза:

```bash
npm run yandex:zip
```

После успешного выполнения загружайте в Консоль Яндекс Игр файл `release/ore-rush-yandex.zip`.

## SDK Яндекс Игр

SDK подключён и инициализируется по [руководству разработчика](https://yandex.ru/dev/games/doc/ru/sdk/sdk-about) (пункт 1.19.1 требований к играм).

- **Подключение.** В `<head>` файла `index.html` — обычный синхронный `<script src="/sdk.js"></script>`. Путь относительный: архив с игрой загружается на сервер Яндекса, а `sdk.js` Яндекс отдаёт сам — скачивать его и класть в проект не нужно. Тег должен оставаться синхронным и стоять выше кода игры: `YaGames` обязан существовать до вызова `YaGames.init()`.
- **Инициализация.** `await YaGames.init()` вызывается один раз, в самом начале (`src/main.tsx` → `src/game/yandex.ts`), параллельно с загрузкой игры. Опциональный параметр `signed` не передаётся: документация советует `signed: false` (поведение по умолчанию), когда платежи обрабатываются на клиенте, — у игры нет своего сервера, поэтому `payments.purchase()` и `getPurchases()` возвращают данные в открытом виде. Если когда-нибудь появится серверная проверка чеков, включать надо будет `signed: true` — тогда ответы приедут только в зашифрованном `signature`.
- **Порядок вызовов.** Методы SDK не используются до завершения `init()`. Всё, что игра сообщила раньше (`LoadingAPI.ready()`, `GameplayAPI.start()` / `stop()`), запоминается и отправляется сразу после `init()`, а не теряется.
- **Вне Яндекса** (`npm run dev`, itch и т. п.) `window.YaGames` нет, и игра работает без SDK. Чтобы в консоли не было ошибки `Unexpected token '<'`, dev- и preview-серверы Vite отвечают на `/sdk.js` пустым скриптом (`vite.config.ts`); в сборку эта заглушка не попадает.
- **Проверка подключения.** `npm run yandex:check` (и `npm run yandex:zip`) читают `dist/index.html` и падают, если тега `<script src="/sdk.js">` нет или он оказался **ниже** кода игры: `YaGames.init()` обязан вызываться после загрузки SDK, иначе лоадер в debug-панели покажет `IF` вместо `IT`. Локально с настоящим SDK игру можно поднять официальным прокси: `npm run build && npm run yandex:proxy` (это `@yandex-games/sdk-dev-proxy --dev-mode=true`, подробности ниже).

### Загрузка игры и разметка геймплея

Сделано по странице [«Загрузка игры и разметка геймплея»](https://yandex.ru/dev/games/doc/ru/sdk/sdk-game-events) (пункты 1.19.2 и 1.19.3). Вызовы идут из `src/App.tsx` по смене фазы игры (`hud.phase`):

| Момент в игре | Вызов SDK |
| --- | --- |
| Загрузка закончена, показано меню | `LoadingAPI.ready()` — один раз за сессию |
| Старт забега, «Продолжить», закрытие инвентаря | `GameplayAPI.start()` |
| Пауза (Esc или кнопка), инвентарь, экран итогов, выход в меню | `GameplayAPI.stop()` |

Оба метода вызываются только тогда, когда игра действительно в этом состоянии: документация требует, чтобы сразу после `GameplayAPI.start()` геймплей шёл, а сразу после `stop()` — стоял. Поэтому `start()` не отправляется «на всякий случай» при возврате на вкладку, если забег ещё на паузе.

Перечень поводов из документации и чем он закрыт в игре:

| Повод из документации | Что делает игра |
| --- | --- |
| `LoadingAPI.ready()` — все ресурсы загружены, интерактивные элементы готовы, экранов загрузки нет | эффект по `hud.phase`: как только фаза перестала быть `loading`, вызов уходит один раз за сессию |
| `start()`: запуск уровня, закрытие меню, снятие с паузы, возобновление после рекламы, возврат на вкладку | фаза `playing` (старт забега, «Продолжить», закрытие живого инвентаря, возрождение после rewarded-видео) |
| `stop()`: прохождение уровня или проигрыш, вызов меню, пауза, показ полноэкранной или rewarded-рекламы, уход на другую вкладку | любая фаза кроме `playing`; уход на вкладку закрывается своим обработчиком `visibilitychange`, который ставит забег на системную паузу |

Инвентарь, верстак и торговец — **живой оверлей поверх идущего забега**: мир, таймер смены, мировые часы и мобы продолжают идти, стоя на месте только сам игрок. Поэтому для платформы экран инвентаря остаётся геймплеем: `GameplayAPI.start()` при нём не вызывается повторно и `GameplayAPI.stop()` не отправляется — индикатор 🎮 остаётся зелёным, ровно как советует методика модерации ([1.19.3](https://yandex.ru/dev/games/doc/ru/requirements/1/19)): «если инвентарь живой — его нужно считать игрой». Красным индикатор становится только на настоящей паузе, где мир действительно заморожен.

Если инвентарь когда-нибудь сделают замораживающим мир, для платформы это станет паузой: понадобится `GameplayAPI.stop()` при открытии и `start()` при закрытии.

Соответствие «фаза → что сказать платформе» вынесено в чистую функцию `yaMarkupForPhase()` (`src/game/yandex.ts`) и закрыто тестом `tools/tests/gameplay-markup.test.ts`: он проходит всю сессию по фазам (`loading → menu → playing → paused → playing → gameover → menu → playing`) и требует, чтобы в SDK ушла ровно одна последовательность `start`/`stop`, а `LoadingAPI.ready()` — ровно один раз. Именно эти два индикатора (фиолетовый Game Ready и зелёный/красный геймплей) модерация смотрит на debug-панели по пункту [1.19](https://yandex.ru/dev/games/doc/ru/requirements/1/19), поэтому регрессия в таблице сразу видна как провалившийся набор, а не как снятая с публикации игра.

Яндекс сам ставит игру на паузу (реклама, окно покупки, смена вкладки, свёрнутое окно, фокус ушёл в другое окно) и **сам вызывает** при этом `GameplayAPI.stop()`, а при возврате — `GameplayAPI.start()`. Поэтому игра следует за событиями `game_api_pause` / `game_api_resume` ([События](https://yandex.ru/dev/games/doc/ru/sdk/sdk-events#pause-resume), `yaOnPause` / `yaOnResume` в `src/game/yandex.ts`): по паузе забег замирает и звук глушится, по возобновлению забег продолжается. Иначе индикатор показывал бы «идёт игра» над замороженной игрой или «остановлено» над идущей. Паузу, которую выбрал сам игрок (Esc), платформа не снимает. После возврата без клика курсор не захватывается сам — игра показывает привычную подсказку «клик — захватить мышь».

Тем же механизмом обрабатывается **стартовая полноэкранная реклама**: платформа показывает её сама у всех игр, и у неё нет callback-ов, как у `ysdk.adv.showFullscreenAdv()`. Поэтому пара `game_api_pause` / `game_api_resume` — единственный способ её отследить, и подписка на неё живёт всю сессию SDK. Звук при этом ещё не запущен: браузеры держат `AudioContext` заблокированным до первого жеста, так что поверх рекламы ничего не играет.

Вне Яндекса возврат на вкладку по-прежнему оставляет экран паузы: сама игра ничего не возобновляет.

### Данные игрока, облачные сохранения и статистика

Сделано по странице [«Данные игрока»](https://yandex.ru/dev/games/doc/ru/sdk/sdk-player).

- **Профиль.** После `init()` игра один раз вызывает `ysdk.getPlayer()` (лимит метода — 20 запросов за 5 минут, поэтому объект мемоизирован) и показывает в меню карточку профиля: аватар и ник из Яндекса. Неавторизованному игроку имя платформы не подставляется.
- **Авторизация — только по желанию.** Карточка гостя предлагает «Войти через Яндекс»: клик сначала разворачивает короткое объяснение выгоды (рекорды и прогресс в облаке, перенос на другое устройство, ник и аватар в игре) и лишь затем открывает `ysdk.auth.openAuthDialog()` — как просит методика модерации ([1.2](https://yandex.ru/dev/games/doc/ru/requirements/1/2)). После успешного входа SDK заново получает `Player`, а `resyncProfile()` перечитывает cloud save авторизованного аккаунта; стартовая функция `startProfileSync()` намеренно запускается только один раз и для этого не подходит.
- **Облачные сохранения.** В облако (`player.setData`, ключ `orerush.profile`) едет компактный профиль: ники, таблица рекордов, выбранный режим, язык и итоговые счётчики. Это то, что переносит прогресс на другое устройство. Полноценный воксельный мир «Моёго мира» остаётся в локальном хранилище: RLE-слепок мира в разы больше лимита облака в 200 КБ на игрока, для такого объёма документация советует собственный сервер — игра честно сообщает об этом в интерфейсе.
- **Слияние при запуске.** Если `savedAt` облачного профиля новее локального, игра принимает облачные рекорды, ник (только если игрок не выбирал свой), режим и язык; иначе отправляет в облако локальный прогресс. Рекорды-заглушки из демо-таблицы никогда не загружаются в облако.
- **Статистика.** Числовые счётчики (`player.incrementStats`) идут отдельно от данных: счётные ключи (добыто блоков, руды, забеги, смерти, убийства, время в игре) инкрементируются, а рекордные (лучший счёт, максимальная глубина) отправляются через `player.setStats` — инкрементировать рекорд нельзя.
- **Лимиты не превышаются.** `player.setData` разрешён 100 раз за 5 минут, статистика — 60 раз в минуту. Все записи идут через очередь в `src/game/profile.ts`: изменения объединяются в батч, отправка — не чаще одного запроса в 3 секунды, плюс немедленный сброс в важные моменты (конец забега, уход со вкладки, `pagehide`). Неудачная отправка не теряется, а возвращается в очередь.
- **safeStorage.** На новейших iOS `localStorage` может очищаться, если игра подключена через свой домен. `ysdk.getStorage()` (`safeStorage`) ставится бэкендом единого фасада `src/game/storage.ts` и дополнительно подменяет глобальный `localStorage`, как рекомендует документация. В архиве для Яндекс Игр это лишь подстраховка: там SDK оборачивает `localStorage` сам.

### Удалённая конфигурация (флаги)

Сделано по странице [«Удаленная конфигурация»](https://yandex.ru/dev/games/doc/ru/sdk/sdk-config). Логика — в `src/game/flags.ts`.

- **Один запрос на старте.** `ysdk.getFlags()` вызывается ровно один раз, после инициализации SDK и чтения профиля. Повторные вызовы в той же сессии не уходят в сеть.
- **Локальная конфигурация всегда с собой.** `LOCAL_FLAGS` — плоский объект из пар «ключ — значение» (только строки, как требует SDK), который передаётся в `defaultFlags`. Игра получает рабочее значение для каждого флага, даже если сервер не ответил.
- **Приоритет.** Свежая удалённая конфигурация → кэш последней удачной конфигурации (если сервер недоступен) → локальная конфигурация. Когда платформа отвечает, её ответ авторитетен: ключ, который убрали из Консоли, возвращается к локальному значению, а не к устаревшему кэшу.
- **Клиентские параметры.** В `clientFeatures` уезжают данные игрока, по которым в Консоли можно строить правила: `lang`, `runs`, `bestScore`, `blocksMined` и `payingStatus` (статус платежной активности из профиля) и `promoId` (акция, по которой игрок пришёл из каталога — см. раздел «Переменные окружения»). Так один и тот же флаг можно включать разным группам игроков.
- **Кэш.** Последняя удачная конфигурация сохраняется в `safeStorage` (`orerush.flags.v1`), поэтому у игрока со слабой связью не пропадают, например, уже отключённые для его группы флаги.

Флаги, которые игра читает сейчас:

| Флаг | По умолчанию | Что делает |
| --- | --- | --- |
| `shop.enabled` | `true` | Показывает/прячет кнопку магазина в меню |
| `game.exploreMinutes` | `20` | Длительность смены в режиме «Исследователь», минуты |
| `ui.showFps` | `true` | Счётчик FPS в углу HUD |
| `adv.enabled`, `adv.interstitial.enabled`, `adv.interstitialCooldownSec`, `adv.rewarded.enabled`, `adv.banner.enabled` | `true` | Реклама: см. раздел про `sdk-adv` |
| `multiplayer.enabled`, `multiplayer.maxPlayers` | `true`, `5` | Кооператив: см. раздел про `sdk-multiplayer-sessions` |

### Реклама

Сделано по странице [«Реклама»](https://yandex.ru/dev/games/doc/ru/sdk/sdk-adv). Логика — в `src/game/ads.ts`, вызовы SDK — в `src/game/yandex.ts`.

- **Полноэкранный блок** вызывается только по действию игрока и только на остановленном геймплее: кнопка «Ещё раз» на экране итогов и «Заново» на паузе. Кулдаун (не чаще, чем раз в 3 минуты, но не менее 60 секунд) и 30-секундная пауза после запуска сессии — свои, сверх платформенных. Реклама никогда не показывается во время активного взаимодействия: по документации случайные клики по блоку сеть считает фродом и снижает доход.
- **Видеореклама с вознаграждением** — единственная, которую игрок запрашивает сам: на экране итогов есть кнопка «Смотреть рекламу · продолжить» с плашкой `AD`, объясняющей, что это рекламный блок. Награда начисляется только после `onRewarded` — этот callback подтверждает засчитанный просмотр; последующий `onClose` не может отозвать уже полученное право на награду. Забег продолжается в том же мире, с половиной здоровья, +60 секундами и тремя секундами неуязвимости. За забег так можно вернуться дважды; при отказе платформы или ошибке до подтверждения игра просто пишет «Реклама сейчас недоступна» и ничего не меняет.
- **Стики-баннер** управляется через `ysdk.adv.getBannerAdvStatus()/showBannerAdv()/hideBannerAdv()` (в Консоли нужно включить опцию «Использовать API для показа sticky-баннера»): в меню и на экране итогов баннер виден, во время забега скрывается, чтобы не закрывать HUD и прицел.
- **Постоянная покупка отключения рекламы** — SKU `disable_ads`; при её владении игровые interstitial и sticky-баннеры отключены. Право восстанавливается через `getPurchases()` и не консумируется; добровольное rewarded-видео остаётся отдельным предложением.
- **Флаги.** `adv.enabled`, `adv.interstitial.enabled`, `adv.interstitialCooldownSec`, `adv.rewarded.enabled`, `adv.banner.enabled` приходят из удалённой конфигурации, поэтому рекламу можно включать и выключать для групп игроков без выпуска новой версии; выключение баннерного флага активно скрывает sticky-баннер, который платформа могла показать по умолчанию.
- **Вне Яндекса** все вызовы — тихий no-op: игра работает на itch или своём домене ровно так же, только без рекламы.
- Звук игры глушится на время показа (`suspendAudio`) и возвращается после закрытия; повторный показ во время уже открытой рекламы невозможен (внутренняя блокировка).

### Магазин и покупки

Реализация опирается на страницу [«Инап-покупки»](https://yandex.ru/dev/games/doc/ru/requirements/1/13) и SDK [покупок](https://yandex.ru/dev/games/doc/ru/sdk/sdk-purchases). Магазин продаёт сами товары по SKU за валюту Яндекс Игр: промежуточного игрового кошелька и наборов внутриигровых монет больше нет. Цены и иконки валюты берутся только из `payments.getCatalog()`; настоящие предложения в Консоли и тестовые покупки ещё нужно проверить вручную. Логика — в `src/game/shop.ts`, `src/game/shopRewards.ts` и `src/game/adFree.ts`; обёртки SDK — в `src/game/yandex.ts`, интерфейс — в `src/ui/Screens.tsx`.

- **Инициализация.** `ysdk.getPayments()` вызывается лениво при первом обращении к платёжному слою, а дальше объект переиспользуется. Вне Яндекс Игр магазин остаётся витриной: платные кнопки недоступны, а цены не подменяются локальными значениями.
- **Прямые товары.** Поддерживаемые одноразовые SKU: `armor-uncommon`, `armor-rare`, `armor-epic`, `netherite-pickaxe`, `netherite-armor`, `chest-common`, `chest-rare`, `chest-epic`, `booster-start`, `booster-ore`, `booster-score`. Карточка показывается как платное предложение, только если активный `payments.getCatalog()` содержит её ID, форматированную цену и иконку платформенной валюты (`getPriceCurrencyImage('small')`). Игра показывает `IProduct.price` как есть — без захардкоженных цен или символов валюты; неполные и отсутствующие предложения скрыты (пп. 1.13.2, 1.13.6).
- **Оплата и награда.** `payments.purchase({ id, developerPayload })` открывает платёжное окно именно для выбранного SKU. Успешная покупка создаёт награду этого товара (снаряжение, припасы или усилитель), а не начисляет баланс. Отмена, нехватка средств и ошибка не меняют игровой инвентарь.
- **Порядок «сохранить → погасить».** Необратимый `consumePurchase()` вызывается только после записи товарного чека и токена покупки в облако (`player.setData`, `flush=true`). Если локальное или облачное сохранение не удалось, покупка остаётся незакрытой и восстанавливается через `getPurchases()` при следующем запуске; устойчивый receipt защищает от повторной выдачи.
- **Старые покупки.** Устаревшие SKU наборов монет и неизвестные товары не зачисляются и не консумируются автоматически. Старый локальный ключ `orerush.diamonds.v1` и поле `diamonds` в облачном профиле удаляются/игнорируются при запуске; это очистка сохранений, а не действующая валюта.
- **Бесплатная реклама — отдельно.** Ежедневные, еженедельные и ежемесячные припасы выдаются только после подтверждённого `onRewarded`; они не требуют покупки и не используют игровой баланс. Платное возрождение удалено, rewarded-возрождение на экране итогов оставлено.
- **Флаг магазина.** `shop.enabled=false` прячет магазин целиком, `true` показывает его в меню.
- **Постоянное отключение рекламы.** `disable_ads` — отдельный SKU с бессрочным entitlement, не набор монет и не расходуемый товар. Кнопка меню появляется только при наличии полного предложения в каталоге. `getPurchases()` восстанавливает владение после перезапуска и смены аккаунта; receipt не консумируется. При владении скрыты игровые interstitial и sticky-баннер, добровольное rewarded-видео остаётся доступно. Стартовая реклама платформы управляется Яндекс Играми отдельно.

**Ручная проверка 1.13 перед публикацией — ещё не выполнена:**
1. В Консоли сверить каждый активный SKU с прямым каталогом товаров выше и отключить устаревшие наборы внутриигровых монет. Проверить в debug-панели, что формат цены и иконка меняются вместе с тестовой валютой.
2. Тестовым покупателем приобрести несколько SKU, проверить соответствующие игровые награды; прервать сеть/обновить страницу после подтверждения оплаты и проверить восстановление чека без потери и дублирования награды.
3. При включённых облачных сохранениях проверить восстановление товарных чеков на другом устройстве под тем же аккаунтом.
4. Отдельно проверить SKU `disable_ads`: покупку, восстановление после перезапуска и на другом устройстве, отключение interstitial/sticky и сохранение добровольного rewarded-видео. Если товара нет или в каталоге неполные данные, предложение должно быть скрыто.

### Мировой рейтинг (лидерборды)

Сделано по странице [«Лидерборды»](https://yandex.ru/dev/games/doc/ru/sdk/sdk-leaderboard). Логика — в `src/game/leaderboard.ts`, обёртки — в `src/game/yandex.ts` (`ysdk.leaderboards.*`), интерфейс — вкладки «Мои смены» / «Мировой рейтинг» в `src/ui/Screens.tsx`.

- **Что завести в Консоли.** Лидерборд с техническим названием `orerush-best-score` (оно же в коде — `LEADERBOARD_NAME`), тип «числовой», сортировка по убыванию. Без такой записи в Консоли запросы отвечают 404 — это самая частая причина «рейтинг не работает» при проверке.
- **Современное API.** Игра обращается к `ysdk.leaderboards` напрямую; устаревший `ysdk.getLeaderboards()` не вызывается (это отдельная проверка в браузерном сценарии).
- **Итог забега.** Каждый законченный забег уходит в `setScore(name, score, extraData)` — в `extraData` едут добытые блоки и материал кирки. Метод доступен только авторизованным игрокам, поэтому перед отправкой игра проверяет авторизацию профиля и `ysdk.isAvailableMethod('leaderboards.setScore')`; анонимный забег остаётся в локальной таблице, как и советует документация.
- **Лимит один запрос в секунду** соблюдается самим модулем: результат, пришедший в ту же секунду, не теряется — запоминается лучший и уходит сразу после паузы.
- **Место игрока.** После забега игра проверяет `ysdk.isAvailableMethod('leaderboards.getPlayerEntry')` и только затем вызывает `getPlayerEntry()`; экран итогов показывает «Ваше место: #N» (или «Вы пока не в рейтинге»). Скрытый профиль обрабатывается отдельно: ник заменяется на «Игрок скрыт», строка остаётся.
- **Топ.** Вкладка «Мировой рейтинг» в меню запрашивает `getEntries({ quantityTop: 10, includeUser: true, quantityAround: 3 })` только при открытии, а не на старте игры; ответ кэшируется, а кнопка «Обновить» заблокирована, пока платформа не разрешит следующий запрос (20 запросов за 5 минут). Ник, аватар и счёт показываются как есть, своя строка подсвечена, название берётся из локализованного `title` лидерборда.
- **Вне Яндекса** вкладка мирового рейтинга не показывается — остаётся только локальная таблица рекордов.

### Кооператив (асинхронный мультиплеер)

Сделано по странице [«Асинхронный мультиплеер»](https://yandex.ru/dev/games/doc/ru/sdk/sdk-multiplayer-sessions). Логика — в `src/game/multiplayer.ts`, фигурки напарников — в `src/game/engine.ts`, обёртки — в `src/game/yandex.ts` (`ysdk.multiplayer.sessions`).

- **Как это устроено.** Своего сервера у игры нет: платформа записывает таймлайн смены (`sessions.commit()`), хранит его и воспроизводит другому игроку событиями `multiplayer-sessions-transaction` / `multiplayer-sessions-finish`. Игра рисует этих игроков «шахтёрами-призраками» в том же мире — так выживание становится сменой отряда до пяти человек.
- **Кто попадает в отряд.** `sessions.init({ count: 4, isEventBased: true, maxOpponentTurnTime: 4000, meta })`: `count` — сколько не хватает до пяти (не больше четырёх напарников, платформа отдаёт до 10 сессий), диапазоны `meta1` (счёт) и `meta2` (глубина) строятся от рекордов игрока, чтобы напарники были примерно его уровня. Без `count > 0` и хотя бы одного `meta`-диапазона платформа инициализируется «только на запись» — поэтому они всегда заданы.
- **Запись.** Движок отдаёт позу игрока четыре раза в секунду, но в таймлайн она попадает реже: не чаще раза в 2 секунды (или в 800 мс, если что-то заметно изменилось) и не больше 1500 транзакций за смену. В payload только шесть коротких полей (`x, y, z, yaw, health, blocks`) — сессия получается около 60 КБ, что с запасом укладывается в лимит 200 КБ.
- **Публикация.** Когда смена заканчивается, `sessions.push({ meta1: счёт, meta2: глубина, meta3: блоки })` отправляется асинхронно; экран сообщает об успехе только после подтверждения SDK. Неудачная отправка не помечается завершённой, а повторный финал продлённой смены может попробовать её снова. Слишком короткие смены (меньше двух транзакций) не публикуются, одинаковые записи повторно не отправляются.
- **Воспроизведение.** Напарник идёт к записанной точке, а не телепортируется, — так выглядит и догоняющая пачка транзакций после фриза. Ник, здоровье и добытые блоки показываются в панели «ОТРЯД» справа во время забега и в таблице отряда на экране итогов; когда запись сессии заканчивается, рядом с именем появляется «ФИНИШ».
- **Вне Яндекс Игр** (itch, свой домен, `npm run dev`) платформы нет — отряд собирается из локальных напарников (`ШАХТЁР-2…5`), которые ходят вокруг игрока. Так же выглядит и режим на предпросмотре. Панель, фигурки и геймплей те же, отличается только отсутствие записи и публикации.
- **Флаги.** `multiplayer.enabled` (`true`) включает кооператив, `multiplayer.maxPlayers` (`5`) задаёт размер отряда — но не больше пяти: это лимит самой игры, из Консоли его увеличить нельзя. Кооператив доступен только в режиме «Выживание»: в «Исследователе» смена одиночная.

### Оценка игры

Сделано по странице [«Оценка игры»](https://yandex.ru/dev/games/doc/ru/sdk/sdk-review). Логика — в `src/game/review.ts`, обёртки — в `src/game/yandex.ts` (`ysdk.feedback`).

- **Сначала разрешение, потом диалог.** Перед запросом игра вызывает `feedback.canReview()` (без него платформа отвечает ошибкой «use canReview before requestReview») и показывает кнопку только при `value: true`. Причина отказа (`NO_AUTH`, `GAME_RATED`, `REVIEW_ALREADY_REQUESTED`, `REVIEW_WAS_REQUESTED`) не выводится игроку: кнопки просто нет.
- **Только по действию игрока.** Диалог открывает кнопка «★ Оценить игру» на экране итогов — то есть после сыгранной смены и по клику, а не автоматически. Это уважительнее к игроку и снимает риск, что окно перекроет геймплей.
- **Один раз за сессию.** Правило платформы продублировано в коде: повторный запрос блокируется, а одновременные клики делят одну проверку и один `requestReview()`; кнопка исчезает, после ответа игра показывает «Спасибо!» или «Как-нибудь в другой раз».
- **Неделя тишины.** Факт показа диалога сохраняется в `safeStorage` (`orerush.review.v1`), и неделю игра оценку не предлагает — даже если игрок просто закрыл окно. При сбое платформы запись не делается, поэтому в следующей сессии запрос можно повторить.
- **Вне Яндекса** кнопки оценки нет вовсе: модуль тихо сообщает `offline`.

### Переменные окружения и переходы по акции

Сделано по странице [«Переменные окружения»](https://yandex.ru/dev/games/doc/ru/sdk/sdk-environment). Логика — в `src/game/promo.ts`, обёртки — в `src/game/yandex.ts` (`ysdk.environment`).

- **Что читается из окружения.** `environment.app.id` (id игры), `environment.i18n.lang` — язык интерфейса Яндекс Игр, по которому игра автоматически выбирает свой язык (п. 2.14), `environment.payload` — параметр `payload` из адреса игры, и `environment.referrer` — диплинк из акционного баннера каталога.
- **Переход по акции не теряется.** Если игра открыта по `?referrer=promo&promo_id=…`, она сразу показывает обещанный экран, а не главное меню: `inapp_id` ведёт в магазин на конкретную покупку (карточка подсвечена и помечена «★ по акции»), известные `promo_intent` (`open_shop`, `open_starter_pack`) открывают магазин, а любая другая акция — например сезонный баннер без сценария — оставляет обычный поток. Платёжное окно само не открывается: финальный клик остаётся за игроком.
- **Аналитика акции.** `promoId` уезжает в `ysdk.getFlags()` клиентским параметром `promoId`, поэтому в Консоли на пришедших по конкретной акции можно нацелить флаги, а в Яндекс Метрике — сравнить поведение групп.
- **Проверка в Консоли.** Для реального перехода нужно создать промоакцию с ID инапа из каталога и проверить её через «В опубликованной версии» и «В черновике»; unit- и browser-проверки используют подменённый SDK и не подтверждают настройки конкретной акции.
- **Вне Яндекса** окружения нет: модуль возвращает `null`, и игра стартует как обычно.

### Серверное время и ежедневная награда

Сделано по странице [«Серверное время»](https://yandex.ru/dev/games/doc/ru/sdk/sdk-server-time). Логика — в `src/game/daily.ts`, обёртка — `yaServerTime()` в `src/game/yandex.ts`.

- **Доверенные часы.** Всё, что зависит от времени (даты сохранений и записей, ежедневная награда, паузы предложений), считается через `ysdk.serverTime()`: время сервера одинаково на всех устройствах и его нельзя откатить, а системные часы игрок может перевести. Вне Яндекса функция спокойно переходит на `Date.now()`.
- **Ежедневная награда.** Бесплатный бонус выдаётся за подтверждённый rewarded-просмотр один раз в календарные сутки по UTC. Первый день серии даёт 8 досок, 6 угля, 3 готового мяса и 4 факела; каждый следующий подряд день добавляет ещё один такой набор, максимум — два набора. Пропуск сбрасывает серию. Припасы сохраняются отдельным receipt для следующего забега, а кнопка после claim блокируется до следующего дня.
- **Дата живёт в облаке.** Запись уходит в облачный профиль (`daily` в `player.setData`), поэтому «раз в сутки» — это про аккаунт, а не про конкретный браузер. Облачный claim сливается даже когда общий `savedAt` профиля старее локального: локальное редактирование другого поля не скроет получение награды на втором устройстве. При слиянии выигрывает более поздняя дата, а при одинаковой — более длинная серия.
- **Защита от накрутки.** Валидная дата из будущего временно блокирует начисление (например, если локальная запись создана по переведённым часам вне Яндекса); повторный вызов в те же сутки ничего не даёт, а перевод системных часов при запущенной платформе не открывает бонус заново. Это покрыто тестами и браузерной проверкой.
- **Еженедельные и ежемесячные рекламные наборы.** В магазине также остаются бесплатные rewarded-дропы: после 7 уникальных дней входа недельное видео выдаёт припасы для следующего забега, а после 30 уникальных дней — материалы для собственного мира. Дни считаются по серверному UTC, пропуски не обнуляют накопленный прогресс; набор фиксируется только после `onRewarded`.
- **Оценка игры и ярлык** тоже считают свои паузы по серверному времени, чтобы перевод часов не возвращал предложение раньше срока.

### События платформы: пауза, «Назад» и выбор аккаунта

Сделано по странице [«События»](https://yandex.ru/dev/games/doc/ru/sdk/sdk-events). Логика — в `src/game/platform.ts`, обёртки — в `src/game/yandex.ts` (`yaOnPause`/`yaOnResume`/`yaOnPlatformEvent`/`yaDispatchExit`).

- **Пауза и возобновление.** По `game_api_pause` движок замирает, а звук глушится, по `game_api_resume` — возвращается; разметка геймплея (`GameplayAPI.start/stop`) следует за фазой. События приходят и от рекламы, и от окна покупок, и от свёрнутого окна браузера, поэтому пауза «от системы» не снимается сама: если игрок поставил игру на паузу сам, `game_api_resume` её не возобновит.
- **Стартовая реклама.** Платформа показывает полноэкранный блок на старте без собственных колбэков — её показ приходит ровно этой парой событий. Состояние доступно через `yaPlatformPaused()`, поэтому игра не запускает цикл и звук «в паузу».
- **Кнопка «Назад» на телевизоре.** `HISTORY_BACK` не закрывает игру молча: появляется собственный диалог «Выйти из игры?» с кнопками «Выйти» и «Остаться», а `ysdk.dispatchEvent(ysdk.EVENTS.EXIT)` уходит платформе только после подтверждения.
- **Диалог выбора игрового аккаунта.** Пока он открыт, таймеры записи данных и статистики остановлены. После закрытия сначала дожидаемся выбранного `Player` и заново читаем его cloud save; старый queued-профиль не отправляется в новый аккаунт. Затем интерфейс принимает выбранный прогресс и возвращается в главное меню.
- **Подписки и отписки.** Подписки на `HISTORY_BACK` и выбор аккаунта снимаются через `off()` при teardown приложения; игровые слушатели и multiplayer возвращают функции отписки. Общие обработчики `game_api_pause`/`resume` живут один раз на сессию SDK, чтобы отслеживать также стартовую рекламу.

### Два способа подключения SDK и колбэки рекламы

Сделано по странице [«Пример»](https://yandex.ru/dev/games/doc/ru/sdk/sdk-example). Логика — в `src/game/yandex.ts` (`waitForYaGames`, `safeCall`).

- **Синхронное подключение** — то, с которым игра выгружается в Консоль: `<script src="/sdk.js">` в `<head>` выше кода игры, `YaGames.init()` один раз.
- **Асинхронное подключение** — второй вариант из документации (`s.async = true`, `s.onload = initSDK`): код игры может выполниться раньше SDK. Игра это переживает: если глобального `YaGames` ещё нет, но страница действительно просит скрипт SDK, игра ждёт его появления (до 5 секунд с шагом 50 мс), а не решает «это не Яндекс Игры» на первом же кадре. Если тега `/sdk.js` нет вовсе (dev-сервер, свой хостинг) — ожидания нет, как и раньше.
- **Колбэки рекламы — как в примере.** Для полноэкранного блока передаются все три: `onOpen`, `onClose(wasShown)` и `onError`; `wasShown` остаётся решающим («была ли показана реклама»), `onError` может прийти и без `onClose`, поэтому игра никогда не зависает за рекламой, а `onClose` срабатывает после ошибки и при слишком частом вызове — обе ветки ведут в одно и то же завершение.
- **Ошибка в колбэке ничего не ломает.** Пример специально бросает исключение внутри колбэка, чтобы показать: остальной код продолжает работать. В игре SDK-обработчики рекламы, `game_api_pause`/`resume`, платформенных и multiplayer-событий защищены: исключение одного обработчика попадает в консоль, но не прерывает остальные подписки и не ломает игру.

### Другие объекты SDK: устройство, полный экран, буфер обмена

Сделано по странице [«Другие объекты и параметры SDK»](https://yandex.ru/dev/games/doc/ru/sdk/sdk-params). Логика — в `src/game/params.ts`, обёртки — в `src/game/yandex.ts`.

- **`deviceInfo`.** Тип устройства берётся у платформы (`type` и хелперы `isMobile()`/`isDesktop()`/`isTablet()`/`isTV()`); если SDK не дал ответа, используются pointer type и user agent. Сенсорное управление появляется на `mobile` и `tablet`, но не на `desktop` и `tv`. Телевизор помечается отдельно — именно туда платформа шлёт `HISTORY_BACK` с диалогом выхода из раздела про события.
- **`screen.fullscreen`.** При открытии настроек игра перечитывает `status`, а кнопка «На весь экран» / «Выйти из полного экрана» снова сверяет его и вызывает `request()`/`exit()` сразу из пользовательского клика, до первого `await` — браузеру нужен активный жест. Собственная кнопка площадки в углу остаётся как есть; вне Яндекса тот же переключатель работает через нативный Fullscreen API.
- **`clipboard`.** Кнопка «Скопировать итог» на экране итогов кладёт в буфер строку со сменой: режим, счёт, блоки, глубину. Внутри платформы вызывается `ysdk.clipboard.writeText()`, вне — `navigator.clipboard`, а в старых браузерах — `execCommand('copy')`; если не сработало ничего, игра честно пишет «Буфер обмена недоступен», а не делает вид, что скопировала.

### Ярлык на рабочий стол

Сделано по странице [«Ярлык на рабочий стол»](https://yandex.ru/dev/games/doc/ru/sdk/sdk-shortcut). Логика — в `src/game/shortcut.ts`, обёртки — в `src/game/yandex.ts` (`ysdk.shortcut`).

- **Сначала проверка, потом кнопка.** Возможность ярлыка зависит от устройства, браузера и платформы, поэтому при запуске игра один раз спрашивает `shortcut.canShowPrompt()` и рисует кнопку только при `canShow: true`. Вне Яндекса и на неподходящих устройствах кнопки нет вовсе.
- **Только по действию игрока.** Кнопка «★ На рабочий стол» живёт в настройках (раздел «Платформа»), рядом с остальными системными опциями: клик открывает нативное окно `shortcut.showPrompt()`.
- **Куда ведёт ярлык.** При первом вызове платформа создаёт ярлык на каталог Яндекс Игр; если он уже есть, следующий ярлык ведёт на саму игру. Игра использует результат SDK и не подменяет назначение ссылки.
- **Награда за ярлык.** За `outcome: 'accepted'` игра один раз ставит в очередь стартовый набор припасов (`SHORTCUT_REWARD_ITEMS`); даже одновременные клики делят одну проверку и одно окно. Награда сохраняется отдельным durable receipt для следующего забега и синхронизируется с профилем.
- **Две недели тишины.** После показа окна (даже если игрок его закрыл) ярлык не предлагается 14 дней; состояние хранится в `safeStorage` (`orerush.shortcut.v1`). Кто ярлык уже добавил, больше не спрашивают вообще.
- **Сбой — не приговор.** Если платформа не открыла окно, ничего не записывается, и в следующей сессии предложение вернётся.

## Требования Яндекс Игр

### Звук вне игры (пункт 1.3)

Сделано по странице [«Звук вне игры»](https://yandex.ru/dev/games/doc/ru/requirements/1/3). Логика — в `src/game/audio.ts`.

Модерация проверяет три ситуации: окно браузера свёрнуто, выбрана другая вкладка, открыто меню выбора вкладок. Игра останавливает звук во всех трёх: модуль звука слушает `blur`, `focus` и `visibilitychange` и держит аудиоконтекст приостановленным, пока фокус или видимость не вернутся. Защёлки независимы друг от друга:

- **фокус и видимость — отдельные сигналы**: `blur` (в том числе меню выбора вкладок, когда документ остаётся видимым) глушит звук; один только `visibilitychange` на видимую вкладку не снимает blur-защёлку — это сделает только `focus`.
- **игра** — пауза движка и платформенные `game_api_pause`/`game_api_resume` держат звук отдельно: его не снимет возврат фокуса (например, под рекламой);
- **реклама** — на время показа звук игры выключен своим флагом, чтобы не спорить со звуком блока, а после закрытия возвращается, только если окно на самом деле в фокусе.

Кнопка «без звука» работает через громкость, а не через приостановку контекста, поэтому не конфликтует с этими защёлками. Юнит-тесты с подменёнными `AudioContext` и SDK проверяют потерю фокуса, переключение вкладки, взаимодействие удержаний, а также `game_api_pause`/`game_api_resume`; browser-сценарий считает `suspend()`/`resume()` при `blur`, `focus` и `visibilitychange`.

### Системный плеер (пункты 1.6.1.6 и 1.6.2.5)

Сделано по странице [«Системный плеер»](https://yandex.ru/dev/games/doc/ru/requirements/1/6). Логика — в `src/game/audio.ts`.

Модерация проверяет, что игра не вызывает системный плеер браузера (значок музыки в панели, плеер в панели уведомлений на телефоне): ни в разметке, ни через Media Session API. Игра синтезирует весь звук через Web Audio, поэтому:

- в исходниках нет ни одного `<audio>`/`<video>`, `new Audio()`, `createElement('audio')`, `HTMLMediaElement`, `srcObject` и picture-in-picture — это проверяет отдельный набор тестов, который сканирует поставляемые файлы (комментарии при этом игнорируются, чтобы пояснения не считались нарушением);
- игра ничего не регистрирует в `navigator.mediaSession` (ни метаданных, ни `playbackState: 'playing'`);
- как страховка при запуске звука и при каждом его возврате медиасессия очищается (`metadata = null`, `playbackState = 'none'`) — «повисший» системный плеер от чужого кода не останется на экране игрока;
- в браузерной проверке мок-медиасессия записывает попытки регистрации, а в DOM считается число медиаэлементов: ноль и там, и там.

**Ручная проверка перед публикацией:** на телефоне запустить игру и открыть панель уведомлений — плеера игры быть не должно; на настольном компьютере включить системный плеер/кнопку управления медиа в настройках браузера и убедиться, что игра там не появляется. Плеер, вызванный музыкой или видео из другой вкладки/приложения, допустим. Headless-тесты не заменяют проверку на реальном телефоне и настольном браузере.

### Адаптация для ТВ (пункт 1.6.3)

Сделано по странице [«Адаптация для ТВ»](https://yandex.ru/dev/games/doc/ru/requirements/1/6/3). Логика — в `src/game/remote.ts`, ТВ-режим в движке — `src/game/engine.ts`, подключение — `src/App.tsx`.

Платформа сообщает о телевизоре через `deviceInfo.type === 'tv'` (см. `src/game/params.ts`), и игра переключается на пульт как на единственный орган управления:

- **Стрелки.** В меню и диалогах они двигают видимый фокус по геометрии элементов (пространственная навигация: ближайший элемент в нажатом направлении, поэтому фокус идёт туда, куда смотрит игрок). Подсветка рисуется классом `.remote-focus`, её видно и без курсора. В забеге стрелки остаются за игроком: вверх/вниз — шаг, влево/вправо — поворот камеры (мыши на пульте нет), вперёд игрок идёт сам, а шаг высотой в один блок берётся автоматически — пульт шлёт по одному нажатию, и воевать с рельефом не нужно.
- **OK (`Enter`).** В меню нажимает выбранный элемент (если фокус ещё не выставлен — сначала ставит его на первый). В забеге удержание OK = удар/добыча, короткое нажатие = использовать предмет перед собой или поставить выбранный блок.
- **Back.** Платформа шлёт `HISTORY_BACK`; правило — в чистой функции `backIntent()`: в меню и на итогах Back сразу открывает окно «Выйти из игры?», а в забеге первое нажатие ставит паузу и открывает игровое меню, второе в пределах 2,5 секунды — то же окно выхода. На некоторых пультах Back приходит как `Escape`: в меню он обрабатывается так же, в забеге сохраняет обычный смысл «пауза/продолжить». Окно выхода помечено модальным диалогом, поэтому пульт навигирует только по нему, и фокус в нём сразу встаёт на «Остаться»: первое нажатие OK не выходит из игры случайно.
- **Без инап-покупок.** На ТВ магазин не показывается, каталог цен и отложенные покупки не запрашиваются, а `ysdk.getPayments()` не вызывается вовсе — платёжный объект игра даже не спрашивает (`paymentsAvailable()` в `src/game/shop.ts`). Ссылок на другие игры у нас нет, а игра занимает весь экран и умеет полноэкранный режим из настроек (sdk-params).
- **Публикация и ручной тест.** В Консоли у игры включается платформа **ТВ**; тот же архив идёт бандлом `games/?bundle=tv`. Проверить на телевизоре можно в приложении Яндекс Игр: на стартовой странице набрать ← ↑ ← ↑ ← ↑ ← ↑ на левом верхнем элементе и ввести ID игры. Headless-сценарий проверяет эмуляцию `deviceInfo.type = tv` и событий пульта, но не заменяет проверку черновика на настоящем ТВ.

### Сохранение прогресса (пункт 1.9)

Сделано по странице [«Сохранение прогресса»](https://yandex.ru/dev/games/doc/ru/requirements/1/9). Логика — в `src/game/profile.ts` (`saveProgressNow`), `src/ui/scores.ts`, `src/App.tsx` и `src/game/engine.ts` (`saveWorld`).

Требование простое: после обновления страницы игрок продолжает с того же места, а прогресс сохраняется сразу после действия, а не по таймеру.

- **Облако + локальная копия.** Рекорды, имя, режим и язык, пожизненные счётчики, ежедневные claim-записи и очереди бесплатных/платных товарных наград (`adDrops`, `shopRewards`) уходят в облако Яндекс Игр (`player.setData`, `player.setStats`/`incrementStats`, см. sdk-player) и одновременно пишутся локально. Игрового валютного баланса в новом профиле нет; старый локальный ключ удаляется, старое облачное поле игнорируется. После добровольного входа профиль выбранного аккаунта перечитывается и применяется до продолжения игры.
- **Сразу после действия.** `saveProgressNow()` (внутри — тот же `flushProfile(true)`) вызывается там, где меняется прогресс: конец смены (рекорд + счётчики), выдача товарного receipt и наград за рекламу, смена имени, режима и языка. Очередь запросов при этом сохраняется — платформа не получает больше, чем разрешают её лимиты (`setData` 100 за 5 минут), просто без задержки на дебаунс.
- **Мир песочницы.** Построенный мир хранится локально (он в разы больше облачных 200 КБ) и сохраняется кнопкой «Сохранить мир», а дополнительно — автоматически в момент `pagehide`/`visibilitychange`, если игрок ушёл со страницы, не нажав её. Автосохранение молчит: баннер не выскакивает поверх игры.
- **Поворот экрана.** Отдельного кода не требует: движок перестраивает canvas по `resize`, а состояние смены живёт в движке, поэтому после поворота на экране та же смена и тот же счёт. Это проверяется в браузере: проверка меняет размер окна и убеждается, что canvas перестроился, сенсорное управление на месте, а игра не вернулась в меню.
- **Ручная проверка перед публикацией.** В Консоли включить для черновика пункт «Поддерживает облачные сохранения» (см. 1.11), затем проверить на реальном аккаунте: гость сохраняет локальный прогресс после обновления, авторизованный профиль читается после входа, а рекорды и товарные receipts появляются на другом устройстве. Снимок мира песочницы намеренно локальный (объём превышает лимит `setData`), поэтому он продолжает жить только на том устройстве, где был построен.

### Корректное отображение (пункт 1.10)

Сделано по странице [«Корректное отображение»](https://yandex.ru/dev/games/doc/ru/requirements/1/10). Логика — в `src/game/viewport.ts`, `src/ui/FitBox.tsx`, стили — в `src/index.css`.

Требование проверяется модерацией так: окно вписывают в 16:9, затем ужимают на 20% по каждой оси и смотрят, не обрезалось и не наложилось ли что-нибудь, нет ли системной прокрутки и не срабатывает ли свайп-обновление.

- **Страница не прокручивается.** `overflow: hidden` на `html/body/#root`, `overscroll-behavior: none` и метатег с `maximum-scale=1`; высота считается в `100dvh`, чтобы мобильная адресная строка не обрезала интерфейс. iOS Safari игнорирует `overscroll-behavior`, поэтому `lockViewport()` дополнительно вешает непассивный `touchmove`: свайп гасится, а если жест начался внутри игровой панели с собственной прокруткой (магазин, итоги) — не трогается, потому что свою прокрутку документация разрешает. Жесты масштабирования тоже гасятся.
- **Ничего не обрезается.** Стартовое меню и экран итогов оборачиваются в `FitBox`: он измеряет содержимое и, если оно выше окна, плавно ужимает его (до 0.42) — вместо того чтобы прятать нижние кнопки за краем экрана. Для телефона в альбомной ориентации (окно высотой ~360 px) есть компактная раскладка в две колонки, а подсказки и панель рекордов уступают место — все кнопки меню остаются на экране.
- **Ничего не накладывается.** Раскладка на сетке, диалоги — модальные окна с собственной прокруткой и `max-height`, поэтому элементы не пересекаются. Хотбар из десяти слотов раньше был шире телефона в портрете и обрезался по краям — теперь он занимает доступную ширину, а слоты остаются квадратными.
- **Управление одной рукой — не подтверждено.** Автопроверка проверяет видимость и минимальный размер сенсорных кнопок, но не реальную досягаемость пальца. Сейчас джойстик движения находится слева, а кластер действий — справа, поэтому по headless-тесту нельзя заявлять, что основной забег управляется одной рукой.

**Ручная проверка 1.10 перед публикацией — ещё не выполнена:** в настольном браузере проверить масштаб 80%, 100% и 125%, изменение ширины/высоты/диагонали окна, вход и выход из полноэкранного режима; в черновике Яндекс Игр включить и выключить sticky-баннер и проверить, что он не закрывает элементы; на телефоне проверить портретную и альбомную ориентации, отсутствие системной прокрутки и swipe-to-refresh, а также пройти забег одной рукой (движение, добыча, прыжок, размещение блока и доступ к инвентарю). Текущая автоматическая вёрстка использует headless Chromium и mock SDK: она не воспроизводит реальное поведение sticky-баннера/полноэкранного окна и не может подтвердить досягаемость органов управления. Если одной рукой управлять неудобно, до отметки «выполнено» нужен одноручный вариант расположения/управления.

### Игровые механики (пункт 2.4)

Сделано по странице [«Игровые механики»](https://yandex.ru/dev/games/doc/ru/requirements/2/4). Требование выполняется, если игра удовлетворяет хотя бы одному критерию; здесь закрыты все четыре.

- **Соревновательные механики.** Счёт забега уходит в мировой рейтинг (`src/game/leaderboard.ts`), в меню виден топ платформы и место игрока, а локальная таблица рекордов хранится в профиле. Сравнивать результаты с другими игроками можно и без облака.
- **Прогресс, зависящий от действий игрока.** Очки набираются за добычу (`def.score × комбо × уровень кирки × количество`), за убийство мобов (с учётом характеристики «жадность»), за продажу предметов и за выполнение заданий; комбо растёт от серии подборов и гаснет по таймеру. Отдельно идёт развитие по дереву крафта: кирка от деревянной до незеритовой, снаряжение, стрелы шести видов, печь-костёр, лук.
- **Цель.** Панель миссий в режиме исследования даёт 36 заданий (`EXPLORATION_TASKS` в `src/game/engine.ts`): набрать древесину, скрафтить кирку каждого тира, добыть уголь/железо/золото/алмазы, найти тайник, приготовить мясо и т. д. Каждое задание даёт очки и добавляет время к смене, так что цель видна и награда измерима. В выживании цель — продержаться до конца смены.
- **Завершение.** Забег всегда заканчивается: `endRun()` вызывается по времени смены, от лавы, от падения и от моба, после чего открывается экран итогов со счётом, статистикой и рекордом. Проиграть можно, «выиграть» — в смысле лучшего личного результата и места в рейтинге.

Юнит-тесты (`survival.test.ts`, `loot.test.ts`, `economy.test.ts`) проверяют начисления, комбо и цены; браузерные сценарии `progress` и `world` проходят смену до экрана итогов и собирают мир песочницы.

### Название игры (пункт 5.1.3)

Сделано по странице [«Одинаковое название игры»](https://yandex.ru/dev/games/doc/ru/requirements/5/1/3). Название игры — **ORE RUSH**, и оно должно быть абсолютно одинаковым в самой игре и во всех материалах черновика для каждого заявленного языка. Документация отклоняет игру даже за другой артикль, пароним, переставленные слова, другое написание или лишнее слово.

Поэтому название живёт в одном месте — `GAME_NAME` в `src/game/brand.ts` — и нигде не набирается заново:

- логотип в меню набран из `GAME_NAME_LINES`, так что две строки «ORE» и «RUSH» не могут разойтись с названием;
- заголовок страницы берётся из `docTitle` выбранного словаря и всегда **начинается** с названия, а после него идёт переведённая подпись жанра — документация прямо разрешает упоминать жанр и ключевые особенности рядом с названием;
- текст «поделиться» (`shareTemplate`) заканчивается точным названием на всех четырёх языках;
- `<title>` в `index.html` — то, что игрок видит до загрузки словарей, — объявляет то же название.

`tools/tests/i18n.test.ts` проверяет все четыре пункта на каждом из четырёх языков: заголовок начинается с `GAME_NAME`, после названия есть подпись, share-текст содержит точное название, логотип складывается в название, а `<title>` в `index.html` совпадает. Переводчик, который «улучшит» название в одном словаре, или теглайн, который заменит название вместо того, чтобы идти после него, сразу роняет набор.

Что остаётся на Консоль: поле «Название» в черновике заполняется вручную для каждого заявленного языка, и оно должно буква-в-букву совпадать с `ORE RUSH`. То же касается иконки и промоматериалов — их нужно сверить глазами.

### Скриншоты для карточки (пункт 5.1.1.2)

Сделано по странице [«Демонстрация геймплея, механики и графики»](https://yandex.ru/dev/games/doc/ru/requirements/5/1/1/2). Кадры снимаются и хранятся в репозитории: `npm run yandex:shots` (сценарий `shots` в `tools/yandex-sdk-check/run.mjs`) поднимает собранную игру в headless-браузере, доводит её до живого забега и снимает кадры 1280×720 в `docs/shots/` — меню, забег, забег вглубь, инвентарь, пауза и возврат из паузы. `SHOTS_LANG` выбирает язык интерфейса, поэтому кадры можно снять на любом из четырёх.

Требование говорит о двух вещах, и они проверяются по-разному:

- **Реальный геймплей, а не заглушка.** Сценарий сам доходит до нужного состояния (меню появилось, `GameplayAPI.start()` ушёл, инвентарь открыт) и только потом снимает кадр, поэтому пустого или недогруженного кадра получиться не может. Сверх этого каждый снятый файл измеряется: доля пикселей, у которых весь блок 6×6 вокруг — ровно одного цвета, должна оставаться ниже 30%. Чёрный экран, полупустой кадр или заглушка дали бы около 100%, живой кадр — единицы процентов (меню 0%, забег 0–1%, пауза 22%, потому что под затемнением остаётся large однородная подложка).
- **Геймплей занимает не меньше 70% картинки, остальное — про игру.** Это правило про промоматериалы, которые загружаются в Консоль вручную: набор кадров выбирает разработчик, и автоматически проверить его нельзя. Поэтому `docs/shots/` — полноэкранные кадры без рамок, где геймплей и так занимает весь кадр, а при сборке карточки в Консоли нужно вручную сверить, что у каждого изображения геймплей ≥ 70% либо остальное место занято текстом, объектами и персонажами игры.

Порог в 30% намерно считается по строго одинаковым пикселям, а не по «почти одинаковым». Как только допуск вырастает до двух шагов, измерение перестаёт отвечать на вопрос «это пустой фон» и начинает отвечать на вопрос «есть ли в кадре плавные градиенты» — а затемнение поверх паузы само по себе на 80% градиент, и объявлять это нарушением было бы честной только на бумаге.

### Расположение рекламы (пункт 4.4)

Сделано по странице [«Расположение рекламы»](https://yandex.ru/dev/games/doc/ru/requirements/4/4). Требование: реклама не мешает игре и показывается только в логических паузах.

Игра — в реальном времени, и уровень в ней длиннее пяти минут («Выживание» бесконечно, «Исследователь» — смена на 20 минут). Документация разрешает такую игре показывать рекламу посреди уровня, но **только** поставив игру на паузу и предупредив игрока таймером на 2 секунды. Игра выбирает более строгий вариант: **внутри смены рекламы нет вообще**.

| Куда ставится реклама | Чем это закрыто |
| --- | --- |
| После запуска игры на платформе | стартовый полноэкранный блок показывает сама платформа; у него нет callback-ов, поэтому игра отслеживает его парой `game_api_pause` / `game_api_resume` (`src/App.tsx`) |
| Неигровое действие — кнопка «Ещё раз» на экране итогов и «Заново» на паузе | `showFullscreenAd()` вызывается прямо в обработчике клика: до вызова SDK нет ни одного `await`, поэтому задержка между действием и началом рекламы — 0 мс (лимит документации — 2 с) |
| Посреди смены | не показывается ничего: ни interstitial, ни баннер — sticky-баннер скрыт на время забега, чтобы не закрывать HUD и прицел |
| Предупреждение с таймером | не нужно: предупреждать обязательно только тогда, когда реклама прерывает идущий уровень |
| Модальные и немодальные окна | инвентарь — живой оверлей поверх идущего мира, магазин и конструктор персонажа открываются из меню, где геймплей уже остановлен |

Поведение замеряется, а не предполагается: браузерный сценарий `progress` в `tools/yandex-sdk-check/run.mjs` нажимает «Ещё раз», запоминает момент клика в собственных часах страницы и требует, чтобы `adv.showFullscreenAdv()` ушёл не позже чем через 2000 мс, а новый забег начался уже после закрытия рекламы. Юнит-тесты `tools/tests/ads*.test.ts` держат остальное: кулдаун, 30-секундную паузу после старта сессии, блокировку повторного показа, договор «награда только по `onRewarded`» и полное отключение игровой рекламы при SKU `disable_ads` при сохранённом rewarded-видео.

### Стики-баннер (`console/adv-monetization#sticky`)

Сделано по странице [«Реклама»](https://yandex.ru/dev/games/doc/ru/console/adv-monetization#sticky), раздел **Стики-баннеры**.

Платформа показывает баннер всю сессию сама, но если в Консоли включена опция **«Использовать API для показа sticky-баннера»**, показом управляет игра. Без этой опции `getBannerAdvStatus()` отвечает `reason: 'ADV_IS_NOT_CONNECTED'`, и никакой вызов `showBannerAdv()` не поможет — поэтому игра один раз запоминает эту причину и не долбит платформу повторными запросами на каждой смене фазы.

**Что делает игра.** `syncBanner()` в `src/game/ads.ts` показывает баннер только там, где он никого не закрывает: в главном меню и на экране итогов. Как только начинается забег, баннер скрывается — иначе он лёг бы на HUD, прицел и сенсорные кнопки. Владение постоянным SKU `disable_ads` тоже скрывает баннер, причём активно: платформа могла показать его по умолчанию ещё до покупки. Флаг `adv.banner.enabled` из удалённой конфигурации выключает баннер для групп игроков без новой версии.

**Что выбрать в Консоли.** Позиция баннера задаётся там же, и от неё зависит, не закроет ли он что-нибудь в меню:

| Платформа | Позиция | Почему |
| --- | --- | --- |
| Телефон, портрет | **снизу** | в меню снизу — кнопки режимов и «Начать добычу»; `FitBox` масштабирует содержимое под окно, но не под окно минус баннер, поэтому баннер сверху закрыл бы заголовок и логотип, а снизу всего лишь сдвигает нижний ряд в собственную прокрутку меню |
| Телефон, альбом | **сверху или снизу** | в альбомной ориентации меню перестроено в две колонки, и верхний ряд с логотипом остаётся на экране в любом случае |
| Десктоп | **справа** | именно там, на широких окнах, стоит панель рекордов (`menu-aside`); включить показ на десктопе можно, но тогда это нужно проверить глазами |

Во время забега баннера нет вообще, поэтому HUD, прицел, хотбар и сенсорные органы управления он не закрывает никогда — это сделано в коде, а не в настройке.

**Ручная проверка.** В черновике нужно включить и выключить sticky-баннер и убедиться, что в меню и на экране итогов он не закрывает кнопки: `FitBox` масштабирует меню под окно, а не под окно минус баннер, так что на самых маленьких размерах (320 × 568) нижний ряд кнопок может уйти под баннер. Проверка идёт вместе с масштабом окна и полноэкранным режимом из пункта 1.10.

### Загрузка игры (`console/add-new-game`)

Сделано по странице [«Загрузка игры»](https://yandex.ru/dev/games/doc/ru/console/add-new-game).

**Шаг 1 — черновик.** Каждая игра получает уникальный ID: новую игру нельзя загружать в черновик, где уже публиковалась другая (пункт 1.24), и нельзя дублировать одну игру в разные черновики (пункт 3.6). Этот проект — один черновик с одним архивом.

**Шаг 2 — архив.** `npm run yandex:zip` собирает ZIP из `dist/` и проверяет требования к архиву: содержимое до сжатия не больше 100 МБ, в корне ровно один `index.html`, в именах файлов и папок нет пробелов и кириллицы (пункты 1.21 и 1.22). Там же проверяется, что `<script src="/sdk.js">` стоит в `<head>` выше кода игры.

**Шаг 3 — черновик.** Поля делятся на **Общее** (общие для всех языков) и **Описание и продвижение** (заполняются отдельно для каждого языка, включая надписи и логотипы на медиаматериалах). Что именно вписывать:

| Поле | Значение |
| --- | --- |
| Название | **ORE RUSH** — одинаково для каждого заявленного языка (пункт 5.1.3) |
| Игра переведена на | `en`, `ru`, `fr`, `de` — ровно те четыре языка, которые есть в словарях (пункт 2.14) |
| Возрастной рейтинг | **12+** — обоснование в разделе про пункт 2.7 |
| Архив | ZIP из `npm run yandex:zip` |
| Иконка и обложка | без интерфейса игры и без плашек «Новая игра», «Акция», «Промо» (пункт 8.3.4) |
| Скриншоты | `docs/shots/*.png`, снятые сценарием `yandex:shots` |

**Шаг 4 — хосты и дистрибуция.** Игре нужен один внешний хост: веб-шрифты Pixelify Sans и Space Grotesk. На вкладке **CSP** указываются `fonts.googleapis.com` (CSS) и `fonts.gstatic.com` (сами файлы) с причиной «веб-шрифты интерфейса». Шрифты загружаются неблокирующе (`media="print"` + `onload`), поэтому первый кадр от них не зависит, а если хосты недоступны, игра остаётся играбельной на `ui-monospace` и `system-ui`. Почти все данные игры лежат в архиве, так что ограничение на объём с внешнего хоста не нарушается. Страны дистрибуции по умолчанию — все.

**Шаг 5 — модерация.** Перед отправкой игра тестируется вручную (`console/test-game`), инап-покупки должны быть подключены с активной ЕЛС, а необработанные платежи закрыты.

### Тестирование (`console/test-game`)

Сделано по странице [«Тестирование»](https://yandex.ru/dev/games/doc/ru/console/test-game). Три способа проверить игру, и все три нужны на разных этапах.

| Способ | Когда | Что даёт |
| --- | --- | --- |
| Dev-окружение | активная разработка | `npm run dev` — файлы локально, платформа не участвует; вся игровая логика, вёрстка, звук и производительность |
| Prod-окружение | финальная проверка перед модерацией | `npm run build` + `npx @yandex-games/sdk-dev-proxy -p dist` (без `--dev-mode`) — файлы локально, но платформа настоящая: авторизация, облако, флаги, покупки, реклама |
| Режим черновика | последний шаг | архив на сервере Яндекса, debug-панель, тестовые оплаты, ТВ |

`npm run yandex:proxy` поднимает dev-вариант прокси (`--dev-mode=true`, мок-SDK, регистрация не нужна) — для проверки подключения. Для прод-варианта нужен черновик и его ID (`--app-id=<ID черновика>`), и именно он отвечает на вопрос «работает ли всё по-настоящему».

**Debug-панель** (`?debug-mode=16` или кнопка **Открыть с debug-панелью** в Консоли) показывает четыре индикатора, и каждый соответствует пункту требований, который уже проверен в репозитории:

| Индикатор | Что должно быть | Чем закрыто |
| --- | --- | --- |
| `IT` / `IF` | `IT` — актуальный лоадер | `<script src="/sdk.js">` в `<head>` выше кода игры, `npm run yandex:check` |
| Game Ready | зеленеет, когда появилось меню | вызов привязан к фазе `loading → menu`, `tools/tests/gameplay-markup.test.ts` |
| 文 | зеленеет на старте, а не посреди игры | загрузчик ждёт `yaReady()`, `tools/tests/sdk-boot.test.ts` |
| 🎮 | зелёный в забеге и в живом инвентаре, красный на паузе, итогах и при уходе с вкладки | `yaMarkupForPhase()`, сценарий `progress` |

**Performance в DevTools** — метрики Game Ready и Time To Interactive. Для игры это время сборки воксельного мира: стартовая область 8 × 8 чанков и превью 3 × 3 в меню генерируются порциями по 7 мс за кадр, поэтому лоадер остаётся живым, а не замороженным.

**Что можно проверить только в Консоли:**

- **Тестовые оплаты.** Аккаунт нужно добавить в **Список логинов для тестовых покупок**, тогда платежи считаются тестовыми и денег не спишутся. После тестов все необработанные платежи должны быть закрыты `consumePurchase()` — иначе модерация невозможна (пункт 1.13.1).
- **Реклама.** Из-за ограничений хостинга реклама может не показываться локально; учёт показов начинается сразу после добавления игры. Проверять показ нужно в черновике.
- **ТВ.** Отдельный режим: пульт, `HISTORY_BACK`, отсутствие магазина (пункт 1.6.3).
- **Sticky-баннер.** Включить и выключить, убедиться, что он не закрывает кнопки меню (пункт 1.10).

## Консоль разработчика

Страницы Консоли описывают то, что нельзя проверить кодом: настройки черновика, покупки, монетизация и тестовая публикация. Ниже — что именно игра ожидает от каждой из них и чем это закрыто в репозитории.

### Инап-покупки (`console/purchases`)

Сделано по странице [«Инап-покупки»](https://yandex.ru/dev/games/doc/ru/console/purchases).

**Что должно быть в Консоли.** На вкладке **Инап-покупки → Инапы** создаются ровно те SKU, которые знает игра (`SHOP_PRODUCT_IDS` в `src/game/shopRewards.ts` и `AD_FREE_PRODUCT_ID` в `src/game/adFree.ts`). Каталог строится из `getCatalog()`, поэтому лишний или отсутствующий SKU в Консоли сразу виден в игре: товар без пары в каталоге скрывается из витрины (пункт 1.13.6), а оплаченный, но не созданный SKU не сможет быть выдан.

| SKU | Что даёт | Тип в Консоли |
| --- | --- | --- |
| `armor-uncommon`, `armor-rare`, `armor-epic` | комплект брони соответствующей редкости | расходуемый |
| `netherite-pickaxe`, `netherite-armor` | незеритовая кирка и броня | расходуемый |
| `chest-common`, `chest-rare`, `chest-epic` | сундук с припасами | расходуемый |
| `booster-start`, `booster-ore`, `booster-score` | усиление на следующий забег | расходуемый |
| `pet-wolf`, `pet-monkey` | питомец навсегда, на аккаунт | **постоянный** |
| `disable_ads` | отключение игровой рекламы навсегда | **постоянный** |

Тип важен: `pet-wolf`, `pet-monkey` и `disable_ads` игра **никогда** не передаёт в `consumePurchase()` — их чеки остаются необработанными, чтобы `getPurchases()` восстанавливал право на любом устройстве и после смены аккаунта. Если такой SKU создать расходуемым, платформа его законсумирует и право пропадёт. Обратное тоже верно: расходуемые SKU игра консумирует, но только после того, как награда и токен легли в облако (пункт 1.13.3).

**Что обязательно до модерации.** Поле **Единая лицензионная схема** в разделе **Профиль** должно быть в статусе **Активен**: при статусах «На проверке» и «Подготовлен» игру с покупками на модерацию отправлять нельзя. Покупки можно добавить заранее, но не публиковать.

Проверка необработанных платежей обязательна для прохождения модерации (пункт 1.13.1) — в том числе для тестовых. Игра вызывает `getPurchases()` на каждом запуске и выдаёт всё, что оплачено, но не доставлено; `consumePurchase()` идёт только после записи в облако, поэтому незакрытый платёж не теряется. Но если в Консоли провести тестовую оплату и не довести её до consume, модерация будет невозможна.

Название и иконка портальной валюты игра не хранит у себя: берёт `price`, `priceCurrencyCode` и `getPriceCurrencyImage()` из каталога (пункт 1.13.2). Поэтому в игре не нужно править цены при изменении курса — они приедут из платформы.

Иконка для диалога оплаты — PNG 256 × 256, до 500 покупок на игру. Всё остальное (реклама, SKU, статистика и выплаты) настраивается в Консоли и в код не попадает.

### Неприятный и шокирующий контент (пункт 8.3.6)

Сделано по странице [«Неприятный и шокирующий контент»](https://yandex.ru/dev/games/doc/ru/requirements/8/3/6). Медиаматериалы не должны сосредотачиваться на туалетном контенте, страшных персонажах и сеттинге или на крови. Неприятный контент внутри игры допустим при возрастной отметке, но в промоматериалах — нет.

**Туалетная тематика.** В игре её нет совсем: ни фекалий, ни туалетов, ни процессов жизнедеятельности, ни соответствующих слов. Как и в пункте 8.3.5, тексты — единственная проверяемая в репозитории часть, и они проверяются: `tools/tests/i18n.test.ts` сканирует значения всех четырёх словарей списком целых слов на четырёх языках (фекалии, мочеиспускание, дефекация, унитаз, скибиди, пуки, подгузники, рвота). Из английского списка намеренно убрано `pet` — в игре продаются питомцы, и слово `pet` значит «животное», а не «туалет».

**Страшные персонажи и сеттинг.** Мобы — зомби, скелет, паук и крипер — нарочно стилизованы: блочные воксельные модели, никакой реалистичной графики, ран и трупов. Урон по мобу — короткая янтарная вспышка материала и золотые искры, смерть — растворение бледно-голубыми пикселями (подробнее в пункте 2.7). Ни один кадр в `docs/shots/` не построен вокруг этого: снимаются меню, забег, инвентарь и пауза.

**Кровь.** Крови нет вообще — ни реалистичной, ни условной. Единственные насыщенно-красные частицы в игре — красное яблоко, которое сыпется из яблоневых листьев (`[220, 60, 50]`), и цвет вулканического камня, когда лава встречает воду (`[85, 45, 49]`); ни то, ни другое не связано с уроном. Эффекты урона и гибели набраны янтарным, золотым, кремовым и бледно-голубым — полный разбор в разделе про пункт 2.7.

Что остаётся на Консоль: иконка, обложка и тексты описания загружаются вручную. На них правило строже, чем в игре: акцент на крови, трупах, туалетной тематике или пугающих сценах — причина отказа или снятия с главной, даже если в самой игре ничего такого нет. Описание и промоматериалы нужно прочитать и просмотреть глазами.

### Эротика и дискриминация (пункт 8.3.5)

Сделано по странице [«Эротика и дискриминация»](https://yandex.ru/dev/games/doc/ru/requirements/8/3/5). Ни игра, ни её материалы не содержат порнографии и эротики, предметов, имитирующих половые органы, отсылок к половому акту, призывов к оголению или механики раздевания, а также ничего, что оскорбляет человека или группу по половому, национальному или религиозному признаку.

В игре этого нет по устройству: единственный персонаж — блочный воксельный шахтёр, конструктор персонажа меняет пол, причёску и цвет одежды, но не снимает её; весь контент — добыча, крафт, мобы, постройка. Ни одного романтического или сексуального сюжета, костюма или текста в игре нет.

Тексты — единственная часть требования, которую можно проверить в репозитории, и она проверяется: `tools/tests/i18n.test.ts` сканирует значения всех четырёх словарей (1968 строк) списком однозначных слов — эротическая и оскорбительная лексика на четырёх языках, включая «раздень», «раздева», «огол» и национальные и религиозные оскорбления. Список намеренно короткий и состоит из целых слов: поиск по подстроке здесь бесполезен — немецкое «Bruststück» (деталь брони) содержит «brust», французское «ci-dessous» содержит «dessous», английское «Striped» содержит «strip». Всё, что слишком расплывчато для автоматики (намёки, контекст, подача), остаётся на ручную сверку.

Что остаётся на Консоль: иконка, обложка и тексты описания загружаются вручную, и на них правило строже, чем в самой игре — эротический кликбейт, цензура кругами, плашки «18+» и фокус на сексуализированных персонажах являются причиной отказа даже если в игре ничего такого нет. Описание и промоматериалы нужно прочитать глазами перед отправкой.

### Элементы интерфейса на медиаматериалах (пункт 8.3.4)

Сделано по странице [«Элементы интерфейса»](https://yandex.ru/dev/games/doc/ru/requirements/8/3/4). Медиаматериалы не должны содержать ни системного интерфейса (статус-бар, индикатор батареи, интерфейс браузера), ни интерфейса Яндекс Игр — бейджей, игрового рейтинга, шапки портала и отладочной панели. Рейтинги и бейджи добавляет сама платформа.

Элементы интерфейса **игры** допустимы — шкала здоровья, таймер, счёт, хотбар, — но не на иконке и не на обложке. Поэтому в репозитории кадры разделены по назначению:

| Файл | Что на нём | Куда можно |
| --- | --- | --- |
| `docs/shots/02-run.png`, `03-run-deep.png` | живой геймплей с HUD (глубина, счёт, хотбар, рука) | скриншоты |
| `docs/shots/04-inventory.png`, `05-pause.png`, `06-after-pause.png` | игровые экраны с интерфейсом и модальными окнами | скриншоты |
| `docs/shots/01-menu.png` | главное меню с логотипом и кнопками | скриншот; обложка — только если меню не читается как элемент интерфейса |
| иконка и обложка | — | в репозитории их нет: они загружаются в Консоль вручную и **не должны содержать HUD** |

Сценарий `shots` в `tools/yandex-sdk-check/run.mjs` снимает кадры в headless-браузере из `dist/` с подменённым `/sdk.js`, поэтому шапки портала, бейджей и отладочной панели на них нет изначально. Это зафиксировано проверкой: страница в момент съёмки не содержит ничего кроме `<div id="root">`, нет ни одного элемента с пометкой рекламного превью и выключен визуальный мок рекламы — иначе включение превью рекламы или отладочного оверлея не смогло бы незаметно попасть в промоматериал.

Что остаётся на Консоль: иконку и обложку нужно собрать так, чтобы на них не было интерфейса игры, и не рисовать на них плашки вида «Новая игра», «Акция», «Промо», «Лучшее!» или число рейтинга — платформа добавляет такие плашки сама, и её имитация является причиной отказа.

### Переводы текстов (пункт 8.2.3)

Сделано по странице [«Переводы текстов»](https://yandex.ru/dev/games/doc/ru/requirements/8/2/3). Словари — в `src/game/i18n.ts`, договор локализации — в `tools/tests/i18n.test.ts`.

Документация разделяет тексты на две группы. **Нужно переводить:** внутриигровую валюту, все кнопки и элементы интерфейса, геймплейные тексты («конец игры», «лучший счёт», «выход»), предупреждения о рекламе и описания управления. В игре всё это переведено: собственной внутриигровой валюты нет — цены и значок валюты берутся из каталога платформы (пункт 1.13), каждую кнопку, плашку рекламы и подсказку управления (`Нажмите E`, `WASD`) набирает словарь, а не код.

**Переводить не нужно** (документация перечисляет исключения): названия клавиш, сокращения и аббревиатуры, имена собственные без официального перевода, окружение, некоторые символы, названия языков, дополнения к элементам интерфейса (`AD`, `NEW`, `DEV`) и названия жанров. Именно из этого списка составлен допуск в проверке «нет двойного перевода»: в русском словаре разрешены `ORE`/`RUSH` (название игры, пункт 5.1.3), `TAB`, `ESC`, `CTRL`, `ALT`, `SHIFT`, `ENTER`, `SPACE`, `AD`, `NEW`, `DEV`, `FPS`, `SDK`, `ID`, `OK`, `YANDEX`, `GAMES`. Всё остальное, написанное латиницей внутри русского словаря, — непереведённая английская надпись, и набор падает.

Проверка смотрит на **значения**, а не на ключи: подстановки вида `{count}` и `{time}` вырезаются до сканирования, потому что это имена переменных, а не текст на экране. Поэтому «Скрафти незеритовых слитков: {count}» — не утечка, а `PRESS START TO PLAY` в русском словаре — да.

Обратное направление закрыто тем же набором: во французском и немецком словарях не должно быть кириллицы, все четыре словаря обязаны покрывать один и тот же набор ключей, без пустых значений и с одинаковыми подстановками. Браузерный сценарий `lang` проходит меню, конструктор персонажа, настройки, магазин, HUD и паузу на каждом из четырёх языков и ищет на экране английские слова из списка «чужого» языка — включая эндонимы в переключателе (`ENGLISH`, `РУССКИЙ`, `FRANÇAIS`, `DEUTSCH`).

### Автоопределение языка (пункт 2.14)

Сделано по странице [«Автоопределение языка»](https://yandex.ru/dev/games/doc/ru/requirements/2/14). Логика — в `src/game/i18n.ts` и `src/game/yandex.ts`.

Игра поддерживает четыре языка — `en`, `ru`, `fr`, `de` — и выбирает их автоматически:

1. **Резервный выбор до SDK.** Пока платформа не ответила, `initLang()` берёт язык из сохранённого выбора игрока, иначе из `navigator.language`, и всё равно приводит его к одному из четырёх через `resolveLang()`.
2. **Язык платформы.** Как только `initYandex()` завершается, `yaLang()` отдаёт `environment.i18n.lang`, и — если игрок сам язык не выбирал — интерфейс переключается на него. Ручной выбор в настройках всегда сильнее автоопределения и переживает перезагрузку (документация это допускает).
3. **Резервные наборы.** Неподдерживаемый код не оставляет игру без языка: `be`, `kk`, `uk`, `uz` дают русский, всё остальное — английский, ровно как в разделе [«Языки и домены»](https://yandex.ru/dev/games/doc/ru/concepts/languages-and-domains#languages). Региональные суффиксы (`uk-UA`, `en-US`) отбрасываются.

**Язык известен до первого экрана.** Индикатор 文 на debug-панели должен зеленить на старте, а не посреди игры: если меню откроется на языке браузера и только потом переключится, модерация увидит именно ту ситуацию, которую её примеры помечают как отказ. Поэтому загрузочная последовательность движка заканчивается задачей, которая ждёт `yaReady()` — флага «SDK ответил». Платформа отвечает за миллисекунды, а `waitForYaGames()` и `YaGames.init()` гарантированно завершаются (у скрипта свой таймаут ожидания, `init()` обёрнут в try/catch), так что лоадер не может зависнуть; `Engine.SDK_SETTLE_TIMEOUT_MS` — страховка от платформы, которая не отвечает вовсе.

Юнит-тест `tools/tests/sdk-boot.test.ts` проверяет, что `yaReady()` поднимается только после `initYandex()`, а `tools/tests/i18n.test.ts` — все четыре словаря, резервные наборы и региональные коды. Браузерный сценарий `lang` открывает игру на каждом из четырёх языков, проверяет переведённость HUD, паузы и подсказок, живое ручное переключение и резервные наборы для украинского и турецкого.

### Длительность контента (пункт 2.9)

Сделано по странице [«Длительность контента»](https://yandex.ru/dev/games/doc/ru/requirements/2/9). Требование выполняется, если основного контента хватает больше чем на 10 минут **или** есть мотивация перепроходить игру; здесь закрыты оба столбца таблицы модерации.

**Много контента.**

- Мир процедурный и бесконечный: чанки генерируются по мере движения (`src/game/world.ts`), поэтому «пройти уровень» нельзя — карта не кончается. 7 климатических зон (зима, равнина, осень, джунгли, пустыня, каньон, вулкан), 154 блока, 33 вида мобов и животных, 55 рецептов крафта.
- Режим «Выживание» бесконечен: смена за сменой ночи становятся опаснее (`survivalThreatLevel()`), враги сильнее и ценнее.
- Режим «Исследователь» — смена на 20 минут (`game.exploreMinutes`) с панелью из 36 заданий, каждое из которых даёт очки и добавляет время.
- Песочница: отдельный сохраняемый мир, который игрок строит сам и который переживает перезагрузку (пункт 1.9).

**Реиграбельность.**

- Новая вселенная одной кнопкой — «СГЕНЕРИРОВАТЬ МИР» пересоздаёт рельеф, зоны и спавн.
- Метапрогрессия между забегами: личные рекорды, мировой рейтинг (`src/game/leaderboard.ts`), питомцы, покупки из магазина, ежедневная награда за серию входов и асинхронный кооператив — поза и финиш соперников подтягиваются в следующую смену.
- Цель развития видна и далека: кирка от деревянной до незеритовой, стрелы шести видов, снаряжение четырёх редкостей.

Браузерный сценарий `world` проходит полный цикл «смена → итоги → реклама → возврат» и собирает мир песочницы, сценарий `progress` — стартует забег на флагах с укороченной сменой.

### Возрастной рейтинг (пункт 2.7)

Сделано по странице [«Возрастной рейтинг»](https://yandex.ru/dev/games/doc/ru/requirements/2/7). Заявляется **12+**; содержание игры проверено по каждому пункту категории.

- **Насилие.** Персонажи полностью вымышленные — воксельные мобы и животные, ни одного реалистичного человека. Графика нереалистична: блочный мир, схематные модели, рэгдолл-физика. Механика урона не выглядит правдоподобной: удар по мобу — короткая янтарная вспышка материала (`src/game/mobs.ts`), золотые искры для врагов и мягкие кремовые частицы для животных с красной шкурой, чтобы удар никогда не читался как кровь (`src/game/engine.ts`). Смерть — не ранение: mob растворяется бледно-голубыми пикселями (или огненными, если сгорел), тела не остаются. Оружие упрощённое и фантазийное — кирка, меч, лук и стрелы; прямых реалистичных аналогов нет.
- **Эротика.** Отсутствует. Единственный «персонаж» — блочный шахтёр, которого можно настроить в конструкторе (пол, причёска, цвет одежды); сексуального контекста, акцента на теле или откровенных нарядов нет.
- **Алкоголь и табак.** В игре нет ни одного такого предмета, рецепта или надписи — ни в мире, ни в магазине, ни в словарях (`src/game/i18n.ts`).
- **Ненормативная лексика.** Отсутствует во всех четырёх словарях интерфейса.

Почему не 6+: в 6+ насилие допустимо только когда оно подразумевается, но не визуализируется как результат. Здесь игрок сам наносит урон, видит полосу здоровья моба, отбрасывание и вспышку попадания — то есть насилие показано, поэтому 6+ заявлять нельзя. Почему не 16+: в 16+ допускаются красная кровь, видимые ранения и реалистичная механика урона — ничего подобного в игре нет, заявлять 16+ тоже не требуется.

Значение рейтинга выбирается в черновике в Консоли (поле «Возрастной рейтинг») и сверяется вручную перед отправкой на модерацию — из кода его не выставить.

### Загрузка и проверка

В [Консоль разработчика](https://games.yandex.ru/console) загружается zip-архив, в корне которого лежит `index.html` из `dist/`.

Локально с SDK игру можно запустить через официальный прокси ([Запуск с локального сервера](https://yandex.ru/dev/games/doc/ru/concepts/local-launch)):

```bash
npm run build
npx @yandex-games/sdk-dev-proxy -p dist --dev-mode=true
```

Игра откроется на `https://localhost:8080` с мок-SDK (регистрация и черновик не нужны); все вызовы SDK логируются в консоль браузера. Без `--dev-mode` прокси запускает игру в prod-окружении — для него нужны регистрация и черновик игры (`--app-id=<ID черновика>`).

#### Автоматические проверки

Кроме ручной проверки в Консоли есть три быстрые команды, которые ловят регрессии без выгрузки архива:

```bash
npm run verify           # всё сразу: сборка → архив → юнит-тесты → проверка в браузере
npm run yandex:check     # требования к архиву + подключение /sdk.js выше кода игры
npm run test:profile     # 50 наборов юнит-тестов на мок-SDK (профиль, флаги, реклама, покупки, лидерборды, кооператив, оценка игры, ярлык, акции, ежедневная награда, события платформы, объекты SDK, подключение SDK, звук, системный плеер, ТВ-пульт, сохранение прогресса, корректное отображение)
npm run yandex:sdk-check # живые вызовы SDK в headless-браузере с подменённым /sdk.js
```

`yandex:sdk-check` поднимает `dist/`, подменяет `/sdk.js` моком из `tools/yandex-sdk-check/mock-sdk.js`
и прогоняет игру в headless Chromium, проверяя по журналу вызовов, что: `YaGames.init()` вызван один раз,
`LoadingAPI.ready()` уходит ровно один раз и уже после появления меню, `getPlayer()` не спамит лимит,
облачные рекорды подтягиваются в меню, `GameplayAPI.start()/stop()` следуют за стартом, паузой и
платформенными `game_api_pause`/`game_api_resume`, что облачные рекорды и статистика уходят в облако по итогам
забега, что rewarded-видео вызывается кликом и возвращает игрока в забег, а полноэкранный блок — действием на
кнопке «Ещё раз». Отдельный сценарий проверяет магазин: каталог Консоли, цены и значки валюты из каталога, прямую покупку SKU с сохранением товарного receipt до `consumePurchase`, отсутствие игрового кошелька и платного возрождения, а также восстановление незакрытой покупки на старте. Лидерборды проверяются там же: вкладка рейтинга в меню тянет топ с
мок-платформы, а после забега уходит `setScore` и на экране итогов появляется место игрока. Кооператив — в забеге
выживания: сессии оппонентов загружаются, поза игрока уходит транзакциями, панель отряда подхватывает транзакцию
соперника и отметку о финише. На экране итогов проверяется и оценка игры: кнопка появляется после `feedback.canReview`,
клик открывает диалог, а второй раз за сессию игра его не предлагает. В настройках проверяется ярлык на рабочий
стол: кнопка после `shortcut.canShowPrompt`, окно по клику и запись одноразового supply-набора. Переходы по акции
проверяются отдельными загрузками страницы: диплинк со скидкой сразу открывает магазин на нужной покупке с
подсветкой и `promoId` в `getFlags`, акция только с `promo_intent` открывает магазин без подсветки, а сезонный
баннер без сценария оставляет игрока в обычном меню. Ежедневная награда проверяется на двух загрузках: в первой
клик по кнопке меню после rewarded-callback ставит ежедневный supply-набор в очередь и пишет claim в облако; повторный клик ничего не дублирует. Во второй сессии серверные сутки сдвинуты без изменения часов браузера, облако отдаёт вчерашнюю дату — игра предлагает двойной набор за серию 2.
События платформы проверяются на экране итогов: `HISTORY_BACK` открывает диалог выхода, «Остаться» его закрывает
без обращения к платформе, «Выйти» отправляет `dispatchEvent(EXIT)`, а после `ACCOUNT_SELECTION_DIALOG_CLOSED`
игра заново читает прогресс и возвращается в меню. Объекты из sdk-params проверяются так: в настройках кнопка
«На весь экран» вызывает `screen.fullscreen.request()` и меняет подпись на выход, повторный клик — `exit()`;
на экране итогов кнопка «Скопировать итог» кладёт в `clipboard.writeText()` строку со счётом; отдельный сценарий
загружает игру с `deviceInfo.type = mobile` (появляются сенсорные элементы управления) и с `desktop` (их нет).
Асинхронное подключение проверяется отдельной загрузкой: тег `/sdk.js` из страницы убирается, скрипт вставляется
с `s.async = true` и отвечает с задержкой, поэтому игра стартует раньше SDK и обязана его дождаться — проверка
убеждается, что `YaGames.init()` всё равно вызван, `LoadingAPI.ready()` ушёл один раз и облачный профиль прочитан. Сохранение прогресса (пункт 1.9) проверяется там же: ежедневный бонус — обычное действие игрока, и проверка убеждается, что запись ушла в облако сразу после клика, без перезагрузки и таймера; затем страница действительно перезагружается, и рекорды, счётчики, имя, claim-дата и очередь припасов должны остаться теми же; старый валютный ключ не восстанавливается. Поворот экрана проверяется на мобильном сценарии (меняется размер окна, canvas перестраивается, смена не сбрасывается), а мир песочницы — в отдельном сценарии: строится мир, вкладка «сворачивается», и снимок мира должен появиться в хранилище без нажатия кнопки сохранения. Вёрстка (пункт 1.10) проверяется отдельным сценарием на шести размерах окна — телефон в портрете и в альбомной ориентации, окно, ужатое на 20% (1093×614), ноутбук, монитор и телевизор: в каждом размере ни одна кнопка не выходит за границы экрана, интерактивные элементы не перекрывают друг друга больше чем на треть, у страницы нет системной прокрутки, `overscroll-behavior` равен `none`, а синтетический свайп вниз не перезагружает игру (`defaultPrevented`); те же проверки повторяются для HUD во время смены. Отдельный сценарий на `deviceInfo.type = tv` проверяет ТВ-адаптацию: магазина в меню нет, `getPayments()` не вызывается, стрелка пульта подсвечивает элемент, переход стрелкой меняет фокус, OK нажимает выбранную кнопку, а `HISTORY_BACK` сначала ставит паузу и только второе нажатие предлагает выйти. Скорость смены для проверки задаётся флагом `game.exploreMinutes=0.25`
(15 секунд), поэтому полный цикл «забег → итоги → реклама → возврат» укладывается в минуту. Браузер берётся из `$CHROME_PATH`,
из dev-зависимости `@sparticuz/chromium` или из системного `chromium`; если ничего нет, проверка честно
пропускается, а не падает.

Перед отправкой на модерацию откройте черновик с debug-панелью (кнопка **Открыть с debug-панелью** в Консоли или `?debug-mode=16` в адресной строке) и проверьте:

- лоадер показывает `IT` (а не `IF`);
- индикатор Game Ready стал зелёным, как только появилось меню игры;
- индикатор языка 文 позеленел на старте, вместе с загрузкой, а не посреди игры (требование [2.14](https://yandex.ru/dev/games/doc/ru/requirements/2/14)) — игра специально не показывает меню, пока платформа не ответила языком;
- индикатор геймплея 🎮 зелёный во время забега и в открытом инвентаре (живой оверлей), красный — на паузе, на экране итогов и при уходе на другую вкладку; после возврата на вкладку (или кнопки **Return the focus to the game** в панели) забег продолжается сам и индикатор снова зелёный, а пауза, поставленная вручную, остаётся.
- перед отправкой на модерацию в черновике нужно выбрать возрастной рейтинг **12+** (требование [2.7](https://yandex.ru/dev/games/doc/ru/requirements/2/7)): игрок может напрямую атаковать и побеждать вымышленных воксельных существ и животных, поэтому насилие не только подразумевается и рейтинг 6+ не следует заявлять. Эффекты попаданий — короткая янтарная вспышка и золотые искры, поражённый моб растворяется бледно-голубыми пикселями; в игре нет изображений крови, реалистичных ран и тел. Значение рейтинга в черновике и итоговый контент нужно сверить вручную — эта проверка пока не выполнена.
